### 4-2. 서비스 테스트 정보 ★사전 준비 필요
- **앱:** 구글/애플/원스토어 중 1개 스토어 등록 URL. **웹:** 접속 가능한 웹사이트 URL.
- **로그인 방식 4유형 중 해당 항목 선택·기재:**
  1. 로그인 불필요 (테스트 계정 생성 불필요)
  2. 별도 로그인 필요 (ID/PW) — 서비스 이용·테스트 가능한 계정 제공
  3. SNS 연동 로그인 (구글·카카오·네이버 등, 테스트 계정 생성 불필요)
  4. 별도 계정 생성하여 로그인 — **지정 형식 확정:**
     - 일반계정 → `ID: openapi` / `PW: 2026openapi!`
     - 이메일계정 → `ID: openapi@메일도메인` / `PW: 2026openapi!`
- **개인 계정 제출 불가.** 위 지정 형식으로 테스트 전용 계정을 생성해야 한다.
- 세 방식 중 **최소 1개** 선택. SNS 연동만으로 이용·테스트가 가능하면 계정 생성 없이 그 방식을 골라도 된다.
- **로그인이 안 되면 서비스 확인 불가 → 심사 제외.**
- → **놀멍봅서 결정:** 유형 4를 택해 `openapi` / `2026openapi!` 계정을 만들고 **그 계정에 성산 전체를 해금**한다. 구글 로그인만으로도 요건은 충족되지만, 유료 구간이 잠기면 심사위원이 핵심을 못 본다.

### 4-3. KTO OpenAPI 활용 정보 ★사전 준비 필요
- 제출 시 **인증키(인코딩/디코딩)** 등 제출. **활용 API별로 서비스 개발 기간 내 호출 이력이 있어야 하며, API 활용 내역을 확인할 예정.**
- **운영계정 신청은 선택 사항** ✅ (대표 1개 API에 대해서만 신청 가능). **인증키(인코딩·디코딩) 제출은 필수.**
  - 참고: 개발계정 = 일 1,000건/오퍼레이션, 운영계정 = 일 100,000건. 성산 1개 장소면 개발계정으로 충분 → **신청하지 않는다.**
- 인정 기준: **실시간 호출(OpenAPI 형태)만 인정** — 파일/맞춤형 다운로드 활용 불인정. 개수 하한 없음("하나 이상").
- ⚠️ **캐싱·로컬 DB 저장은 권고되지 않는다.** FAQ 원문: *"데이터 동기화 오류 방지를 위해 로컬 DB 저장 방식이 아닌 **실시간 호출 방식으로 활용하실 것을 강력히 권고**"*, *"로컬 DB 저장 방식을 사용하여 개발 기간 내 **API 호출 이력이 확인되지 않을 경우 심사에서 불이익**"*. 부득이한 경우 **별도 신청서**가 필요하며 tourapi@knto.or.kr로 문의.
  - → **놀멍봅서 조치:** `place.py`·`tourist.py`의 `CACHE_TTL`을 **7일 → 1시간**으로 변경 (2026-08-13 결정). 7일이면 개발 기간 전체에 호출 20여 건뿐이다. **완전 제거는 하지 않는다** — 개발계정 한도(오퍼레이션당 일 1,000건)에 하루 50명 수준에서 걸리고, 차단되면 `place.py:134`가 빈 필드로 200을 반환해 조용히 정보가 사라진다. 상세 → `../기획/설계_현장플레이.md`
- 저작권: 소유권은 참가자. 단 **"한국관광공사/KTO" 명칭·로고 사용 금지** (FAQ에 출처 표기와의 충돌 관련 항목 존재).
- 트래픽: 개발계정 일 1,000건/오퍼레이션, 운영계정 일 100,000건. 서비스키 유효 2년.

### ☐ 1. 앱스토어 등록 착수 — ★최우선 · 미착수
애플 앱스토어(또는 구글 플레이·원스토어 중 1개) 등록·승인 완료. 스토어 등록 URL 제출이 **자격 요건**이고 **추가 기간 없음**, 마켓 등록 교육도 미진행 → 리젝 대응을 자체 감당. 초회 등록은 개인정보 처리방침·위치권한 사용 사유·계정 삭제 경로에서 리젝이 흔함.
- ✅ 애플 개발자 계정 보유 확인 (2026-08-13)
- ✅ 스코프 결정 완료 — 설계 문서 §7 **단계 1 종료 시점에 첫 등록**(콘텐츠 완성 전이라도). 콘텐츠는 업데이트로 채운다.

### ☑ 2. 운영계정 — 해결 (2026-08-13)
**선택 사항**으로 확정. 성산 1개 장소면 개발계정(일 1,000건/오퍼레이션)으로 충분하므로 **신청하지 않는다.** 단 **인증키(인코딩·디코딩) 제출은 필수.**

### ☐ 2-B. KTO 호출 이력 확보 — ★신규, 자격 요건
`CACHE_TTL` **7일 → 1시간** (`place.py:18`, `tourist.py:18`). 완전 제거는 개발계정 한도 때문에 하지 않는다.
**며칠 뒤 공공데이터포털 마이페이지에서 실제 호출 건수를 확인해 조정한다.** (§4-3 · 설계 문서 §6)
집중률 API를 붙일 경우 그것만 TTL 5~10분 또는 캐시 없이 — "지금 붐빔"이 1시간 전 데이터면 무의미하다.

### ☐ 2-C. 위치 전송 경로 차단 + 사전 검토 — 법적 요건
**정정(2026-08-13):** `/place/detail`이 보내는 좌표는 **관광지 좌표**이지 사용자 위치가 아니다. 확인 결과 **현재 앱은 사용자 위치를 서버로 전송하지 않아 신고 대상이 아니다.**
남은 작업: 미사용 죽은 코드(`PinsAPI.fetch(lat:lng:)`, `/pins` 좌표 엔드포인트)를 제거해 구조적으로 막고, 위치정보지원센터(www.lbsc.kr / 02-588-0185) 사전 검토를 받는다. (§7)

### ☐ 3. 심사용 테스트 계정 경로 마련
`ID: openapi` / `PW: 2026openapi!` 계정을 만들고 **그 계정에 성산 전체를 해금**한다. **개인 계정 제출 불가 · 로그인 실패 시 심사 제외.** 현재 Google Sign-In만 존재(`ios/…/LoginSheet.swift`, `backend/services/auth.py`)이므로 **ID/PW 로그인 경로를 신설**해야 한다.
같은 계정을 **애플 앱스토어 심사용 로그인 정보**로도 제출한다 (두 곳 겸용).

**가능.** FAQ 원문: *"기 제출한 제안서 내용에서 변경사항(개선, 수정 등)이 있을 경우 서비스 개발시 반영하여 진행하시면 됩니다. 1차 심사자료 제출시, 기능설명서에 해당 부분 반영하여 제출."*
