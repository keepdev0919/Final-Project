## 확정 사항 (07-20)

### 1. 본질 재정의 — 정보가 아니라 경험
- **한 줄 정의 (확정):** 제주를 방문하는 **소규모 여행자**가 가진 **전문 가이드 없이 관광지를 깊이 경험하기 어려운 문제**를 **현장 참여형 AI 스토리 경험**으로 해결하는 **여행 서비스.**
- **문제 정의 (확정):** 소규모 여행자는 전문 관광가이드를 이용하기엔 **비용 부담**이 크고, 단체 가이드는 **개인의 속도와 관심사에 맞는 설명 및 상호작용**을 제공하기 어렵다. 이로 인해 관광지에 담긴 **역사와 이야기, 문화적 맥락**을 충분히 이해하지 못한 채 여행을 마치는 경우가 많다.
- *정보가 아니라 경험을 판다.*

### 2. 설화·민담 = '데이터1'로 강등
- 이 프로젝트는 "설화 데이터로 뭘 하지?"에서 출발해 설화가 *목적*처럼 취급됐고, 그게 제품 가치를 약하게 만든 근본 원인이었다.
- 이제 설화는 **여러 콘텐츠 재료 후보 중 하나**일 뿐이다. 장소에 따라 지질·역사·사람·감각 등 어떤 **렌즈**든 재료가 될 수 있다.
- 진짜 질문: *"이 장소를, 그냥 온 사람과 완전히 다르게 보고 떠나게 하려면 뭐가 필요한가?"* — 그 답의 재료가 설화면 설화를 쓴다.

### 3. 타겟 경험 = "정서적 연결 + 관점 전환"의 융합 (확정 2026-07-20)
- **성산을 떠날 때 남아야 하는 것 = ① 이 장소가 나에게 의미 있게 다가온 정서적 연결(뭉클/소름) + ② 몰랐던 걸 알고 나니 풍경이 다르게 보이는 관점 전환.** 이 둘의 **융합**이 "돈 값".
- **③ 능동 발견·참여는 목적이 아니라 ①②를 만들어내는 수단.**
- **근거:** 사용자 본인 여행 관점 반추(2026-07-20) + 해설학(Tilden — 해설의 목표는 정보 전달이 아니라 provocation·방문자 개인과의 연결·더 큰 whole의 revelation).
- **설계 함의:** 각 비트의 payoff(재관찰 순간)는 **"다르게 보임(②) + 뭉클함(①)"을 동시에** 내야 함. → 단순 사실·트리비아 배제, **관점을 뒤집으면서 감정을 건드리는 맥락만** 채택. 비트 명세의 **품질 게이트**로 명문화 예정.
- 렌즈(지질/역사/사람/감각)는 여전히 장소별 미정 — 타겟 경험(①+②)은 렌즈와 무관하게 성립.
- (구 프레임 ①②③ 택일은 폐기 — 미검증 도구였음.)

### 4. 해자 = "현장에서 눈앞의 것에 반응하는 대화"
- 훌륭한 가이드가 하는 것: A.시선 유도 · B.호기심 갭 · C.맥락 연결 · D.개인화 대화 · E.페이싱.
- 이 중 **ChatGPT·안내판·비짓제주가 죽어도 못 하는 것 = A(시선 유도) + D(개인화 대화)를 "지금 그 자리에서" 동시에** 하는 것. 이게 유일한 해자이고, 엔진은 이걸 중심으로 짠다.

### 5. 엔진 큰 그림 — 관찰 지점들의 경로
- 장소 = `[관찰지점 1] → [2] → [3] → … → 마무리` 의 경로.
- 각 관찰지점 = 반응형 대화 루프 한 바퀴(시선 유도 → 호기심 갭 → 사용자 반응 → 맥락 연결 → 재관찰 → 다음).
- **RAG는 강등**: 콘텐츠 뼈대가 아니라, 사용자가 중간에 옆길로 새는 자유 질문을 받아주는 **바닥 보조**.
- ⚠️ 관찰지점 내부 문법(관찰타겟·갭·페이오프 같은 구조)은 **아직 확정 아님** — 리서치 결과 위에서 재설계(아래 보류 참조).

### 6. 위치 앵커링 = GPS 웨이포인트 + 자기보고
- v1: 경로에 좌표 찍힌 관찰지점을 GPS로 발동 + 사용자 "다음 지점 도착" 자기보고로 GPS 오차 보정.
- 카메라 비전(폰 들면 AI가 봄)은 해자를 극대화하지만 신뢰성·비용 리스크로 **백로그**.

### 7. 아키텍처 = "레일 위의 자유 대화" (template = engine)
- **비트 명세(콘텐츠 템플릿)**: 작가가 관찰지점별로 채우는 뼈대. 유료 품질이 여기서 나온다. 장소마다 다시 채움 → 확장 시 템플릿화되는 부분.
- **재사용 런타임 엔진**: 비트 명세들을 들고 사용자를 반응적으로 통과시키는 대화 관리자. 한 번 만들면 모든 장소 재사용.
- 콘텐츠 제작과 엔진이 깔끔하게 분리 = 사용자가 원래 세운 전략("1개 완성 → 템플릿화 → 확장")의 실체.

### 8. 전략 — 1개 압도적 완성 후 확장 (양산 지양)
- 사용자는 단건 결제. **10개의 평범한 콘텐츠보다 1개의 압도적 콘텐츠가 중요.**
- 순서: **성산일출봉 1개 압도적 완성 → 현장 검증 → 유료 가치 검증 → 제작 프로세스 정립 → 다른 장소 확장.**
- ⚠️ 07-14의 "90개소 양산" 로드맵은 이 전략과 충돌 → 폐기.

### 9. 게임화 = 목적 아닌 수단으로 격하 (확정)
- 게임 요소(미션·선택·수집)는 **몰입을 돕는 수단**일 뿐, 제품 정의가 아니다. "AI 관광 RPG"는 폐기.
- 문서에서 "게임화 레이어/RPG"를 제품 축으로 내세운 서술은 제거 대상.

### 10. 무료 기능 유지
- 비짓제주 검증 코스 추천(~9,000 코스)은 무료 유입 훅으로 **유지.** (⚠️ 문서 정리 시 설화와 싸잡아 지우지 말 것.)

## 보류 사항 (리서치·설계 확정 후 결정)

1. **관찰지점(비트) 내부 문법 — 🟡 재료 확보, 템플릿 작성 대기:** guided looking(시선유도→관찰→맥락→재관찰) + 해설학 TORE(주제·구성·관련성·즐거움) + O-Mopsi 5원칙(매력도·접근성·위치 명료성·식별 용이성·수명) + Detour 스키마(`{이름, 위치+반경, 대사, 트리거}`)로 문법·품질기준·데이터양식 확보. → "비트 명세 템플릿 v1"로 조립하면 됨.
2. **음성 vs 텍스트 모달리티 — ✅ 해결 (2026-07-20, 사용자 도출):**
   - **오디오 내레이션이 코어** (북극성 = "폰 적게 보기", 눈은 풍경에 → guided looking 성립). 코어 음성은 **미리 생성/녹음해 품질 통제**(실시간 TTS 아님, Detour식).
   - **대화는 온디맨드 레이어**(질문 생겼을 때만). **음성 우선(음성 in/out) + 타이핑 동등 폴백**(야외·공공장소 민망함 대비).
   - **화면 역할 최소화:** 제어(도착 버튼·재생) + 가끔 시각 보조(지도·사진) + 폴백.
   - 감정 절정 비트는 **사람 성우 녹음 옵션**(TTS가 "뭉클"에 반 발 못 미침) — 성산 콘텐츠 보며 결정. 실시간 TTS는 비코어(자유질문 답변)에만 → 리스크 작음.
3. **성산일출봉의 렌즈(지질/역사/사람/감각)와 비트 개수** — 장소별로 다르므로 엔진 확정 후 개별 결정.
4. **단건 결제 가격·수익모델·저작 프로세스** — 3층 BM(아래 보존) 위에서 구체화. (공모전은 결제 자체보다 완성된 서비스·데이터활용을 봄 → 결제는 후순위 가능.)
5. **타겟 청중** — "지적 발견형 여행자" vs 그 외. **결정 보류.**
