# 성읍 생활기록 복원작전

> 이 문서는 `성읍민속마을` PLAY 콘텐츠의 단일 정본이다.
>
> 공통 제작 규칙은 `../콘텐츠.md`, 외부 레퍼런스는 `../레퍼런스.md`, Place/KTO 데이터 정책은 `../데이터.md`를 따른다.
>
> **현재 방향**
> - Odii 대본은 최종 Story가 아니라 콘텐츠 제작 원천자료 중 하나로 취급한다.
> - PLAY Story는 Odii·국가유산·공식/전문자료를 교차검증해 놀멍봅서가 별도로 작성한다.
> - Story 텍스트와 TTS 원본은 동일한 `story.script`를 사용한다.
> - PLAY 상세에는 START / 주요 Point / FINISH를 한눈에 보여주는 **탐험 경로 지도**를 포함한다.
> - 이 파일에는 실제 채택된 PLAY 콘텐츠와 구현에 필요한 정보만 남긴다. 검토 후 제외된 후보 장소/아이디어는 기록하지 않는다.

## 4. 탐험 경로 지도

### 역할

PLAY 상세의 지도는 메인 `지도` 탭과 다른 기능이다.

- 메인 지도 탭:
  - **제주 어디에서 PLAY할 수 있는가?**
- PLAY 상세 지도:
  - **이 PLAY는 어디서 시작해서 어디를 돌아다니는가?**

### 성읍 지도 표시

성읍은 다음 전체 Point를 **미리 공개해도 되는 PLAY**다.

이유:

- 이 PLAY의 재미는 다음 목적지를 추리하는 데 있지 않다.
- 각 Point에 도착해서 현실의 건축·생활 흔적을 관찰하는 것이 핵심이다.

따라서:

`routeRevealMode = FULL`

### 지도 표시 대상

- START
- P1 대장간집
- P2 객주집
- P3 한봉일 고택
- P4 고창환 고택
- FINISH

### 지도 시각 규칙

- START: 별도 Start 마커
- FINISH: 별도 Finish 마커
- Point: 순서가 읽히는 번호 마커 `1 / 2 / 3 / 4`
- 현재 선택 Point: 크기 또는 형태 변화
- 색만으로 상태를 구별하지 않음

### 경로선

실제 보행 경로 데이터가 검증되어 있으면 실제 route polyline을 표시할 수 있다.

검증된 실제 보행 경로가 없다면:

- Point를 직선으로 연결해 길처럼 보이게 하지 않는다.
- Point 번호와 순서만 표시한다.
- 실제 이동은 `[길찾기]`로 외부 지도 앱에 맡긴다.

### 좌표 데이터

개발 데이터에는 아래 구조를 둔다.

```text
start
- name
- lat
- lng

points[]
- id
- name
- lat
- lng
- order

finish
- name
- lat
- lng

route
- distanceMeters
- estimatedMinutes
- revealMode
```

### 좌표 검증 원칙

- Point 좌표는 Odii / 공식 문화유산 / 공공 지도 / 신뢰 가능한 장소정보로 확인한다.
- 추측 좌표를 사용하지 않는다.
- 무료공영주차장 START/FINISH 좌표도 출처 확인 후 잠근다.

## 5. Story / TTS 원칙

### 기본 Loop

```text
Mission
→ 현실 관찰
→ Answer / Verify
→ Discovery
→ 필요할 때 Story
→ Story script 그대로 TTS
→ Progress / NEXT
```

### Discovery와 Story

**Discovery**
- 사용자가 방금 현실에서 확인한 사실
- 짧고 구체적
- 역사 설명을 길게 넣지 않음

**Story**
- 방금 발견한 것이 왜 의미 있는지 설명
- Mission 전에 정답을 알려주지 않음
- Odii 대본을 그대로 재생하지 않음

### Story 길이

- 기본: 약 15~35초 TTS
- 중요 Story: 가급적 45초 이내
- 필요한 내용을 억지로 줄이기보다 Mission과 직접 관계없는 설명을 덜어낸다.

### Story 자료 구조

```text
Story
- id
- title
- script
- sources[]
- ttsEnabled
```

`script` 하나를:

- 화면 텍스트
- TTS 음성

에 공통 사용한다.

### 자료 역할

```text
Odii
국가유산포털
한국민족문화대백과
VisitJeju / 제주 공식자료
기타 신뢰 가능한 전문자료
        ↓
Reality Evidence / Story Sources
        ↓
놀멍봅서 자체 Story
        ↓
TTS
```

Odii `stid`는 출처 식별자로 보관할 수 있지만 Mission Clear 시 Odii 원문을 자동 재생하지 않는다.

## 6. 공통 PLAY 규칙

1. 화면의 설명보다 실제 장소를 먼저 본다.
2. 핵심 정답은 현실에서 관찰 가능한 단서로 해결한다.
3. 기본 구조는 `관찰 → 해결/검증 → 발견 → 의미`.
4. Story는 발견 뒤에 제공한다.
5. Mission 하나는 여러 Step을 가질 수 있다.
6. `[찾았어요]`만으로 핵심 Mission을 끝내지 않고 가능한 경우 Verify를 둔다.
7. Hint 1은 **어디를 볼지**, Hint 2는 **무엇을 볼지** 알려준다.
8. 모든 Main Mission은 Skip 가능하다.
9. Skip 때문에 PLAY가 막히지 않는다.
10. Mission 개수를 맞추려고 약한 Mission을 추가하지 않는다.
11. PLAY의 Point와 Mission 수는 같을 필요가 없다.
12. 위치는 보조수단이지 정답 판정기가 아니다.

# 21. 변경 관리

이 파일이 성읍 PLAY의 **단일 콘텐츠 정본**이다.

다른 문서에는 성읍 Mission / Story 전문을 중복 복제하지 않는다.

- 공통 PLAY 제작 규칙 → `../콘텐츠.md`
- 레퍼런스 분석 → `../레퍼런스.md`
- Place / KTO OpenAPI 정책 → `../데이터.md`
- 성읍 PLAY / Mission / Story / Route / Final → **이 문서**

### 문서에 넣지 않는 것

- 검토 후 제외된 후보 Point의 상세 판정 기록
- 미채택 Odii Story 목록
- 폐기된 Mission 초안
- 임시 아이디어

필요한 경우 별도 작업 로그에서 관리하고, 이 정본에는 최종 채택 내용만 유지한다.
