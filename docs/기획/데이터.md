# 데이터

> **책임:** 놀멍봅서 V1에서 실제로 사용하는 관광 데이터와 API의 역할, 저장/호출 방식, 출처·저작권 제약을 정의한다.
>
> 콘텐츠를 어떻게 만드는지는 `콘텐츠.md`, 제품 범위는 `../../CLAUDE.md`가 이긴다.

---

## 1. V1 데이터 전략

### 핵심 원칙

> **오디(Odii)가 V1 콘텐츠 공급의 중심이다.**

현재 구조:

```
Odii 제주 이야기/장소
    ↓
콘텐츠 후보 풀
    ↓
콘텐츠.md 기준으로 플레이 가능성 판정
    ↓
Top 5
    ↓
현실 미션 + Odii 이야기
```

---

## 2. Odii의 역할

한국관광공사 오디오 가이드 OpenAPI를 사용한다.

Odii가 제공하는 주요 정보:
- 장소/이야기 제목
- 위도·경도
- 이야기 ID
- 대본
- 재생 시간
- 오디오 URL(있는 경우)
- 언어
- 이미지 등 API 응답 필드

### 제품에서의 역할

Odii는 **WHAT**을 제공한다.

> 이 장소에 어떤 역사·인물·의미·이야기가 있는가?

놀멍봅서는 **HOW**를 만든다.

> 사용자가 현장에서 무엇을 보고, 무엇을 발견한 뒤 그 이야기를 만나게 할 것인가?

따라서 차별점은 데이터를 새로 쓰는 데 있지 않고,
**공식 관광 해설을 현실 행동으로 전환하는 방식**에 있다.

---

## 3. 저장과 실시간 호출

### 로컬/서버에 저장하는 것

장소를 찾고 홈/지도/후보 분석에 필요한 **메타데이터**는 저장할 수 있다.

예:
- `stid`
- 제목
- 좌표
- 재생시간
- 스크립트/오디오 존재 여부
- 장소 묶음 정보

### 저장하지 않는 것

Odii의 대본 전문과 오디오 파일은 저장·캐시하지 않는다. 사용자가 이야기를 열 때마다 Odii OpenAPI를 실시간 호출한다.

### 이야기 재생

사용자가 현장에서 이야기를 열 때:

```
Point 발견
   ↓
서버
   ↓
Odii OpenAPI 실시간 호출
   ↓
대본 / audioUrl
   ↓
클라이언트 재생
```

이 구조는:
1. 한국관광공사 콘텐츠를 자체 DB에 대량 적재·재배포하는 모양을 피하고,
2. 공모전에서 실제 KTO OpenAPI 활용과 호출 이력을 보여주기 위해 유지한다.

---

## 4. Odii 조회 방식

Odii API 특성상 저장된 이야기 ID 하나만으로 원하는 상세를 바로 가져오기 어려운 경우,
서버는 저장해 둔 **Odii 좌표 주변을 다시 조회**해 해당 `stid`를 찾는다.

중요:

> **이 좌표는 사용자의 현재 위치가 아니라 Odii에 저장된 관광지 좌표다.**

클라이언트의 사용자 GPS를 Odii 대본 조회 목적으로 서버에 보내지 않는다.

---

## 5. 위치 데이터

### 사용자 위치

- iOS/클라이언트에서 현재 위치를 얻는다.
- 거리 계산은 가능한 한 **클라이언트 로컬**에서 한다.
- 서버에 사용자의 지속적인 실시간 위치를 보내는 구조를 V1 기본값으로 삼지 않는다.

### GPS가 하는 일

GPS는 주로:
- 관광지에 도착했는지
- 시작점 근처인지

를 보조한다.

세부 Point가 가까이 붙어 있는 경우 GPS로 정확히 구분하려 하지 않는다.
콘텐츠 진행은 `콘텐츠.md`의 **현실 관찰 + 발견 확인 + 자기보고** 방식이 담당한다.

---

## 6. 스크립트와 오디오

Odii의 모든 이야기가 오디오 파일을 제공하는 것은 아니다.
기존 데이터 점검에서는 **스크립트는 있으나 오디오가 없는 항목이 상당수** 확인됐다.

따라서 장소 후보 평가 때:
- `has_script`
- `has_audio`

를 별도로 본다.

---

## 7. KTO OpenAPI와 공모전

웹·앱 개발 부문에서 한국관광공사 OpenAPI 활용은 핵심 요건이다.

출시/심사 전 확인:
- 실제 운영 계정/활용신청 정보가 맞는지
- 서비스에서 실제 API가 호출되는지
- 호출 이력이 남는지
- 제출 자료에서 API가 어느 화면/경험에 쓰이는지 설명 가능한지
- 앱스토어 등록이 완료됐는지

놀멍봅서에서는 OpenAPI가 장식이 아니라:

> **현실 미션을 성공한 뒤 의미를 제공하는 핵심 이야기 데이터**

로 사용된다.

## 8. 보조 데이터

V1에서 새로운 데이터 소스를 기본 파이프라인에 계속 추가하지 않는다.

필요한 경우에만 사용:
- 관광지 대표 이미지/기본 정보
- 지도 표시
- 사실 검증
- 운영시간/접근성 확인

새 데이터 소스를 쓰기 전에는:
1. 정말 Top 5 출시에 필요한가?
2. Odii만으로 해결할 수 없는가?
3. 이용허락/출처 조건이 명확한가?
4. 유지보수할 API가 하나 더 생기는 가치가 있는가?

를 확인한다.
