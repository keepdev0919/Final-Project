# 레퍼런스 — 현장 탐험 콘텐츠 제작 문법

> **책임:** 놀멍봅서 V1의 현장 게임 콘텐츠를 만들 때 참고할 **외부 레퍼런스의 실제 플레이 구조와 제작 규칙**을 정리한다.
>
> 이 문서는 `콘텐츠.md`보다 한 단계 앞의 **벤치마크 기준서**다.
> - `레퍼런스.md` = 실제 서비스들은 어떻게 만드는가
> - `콘텐츠.md` = 그중 무엇을 놀멍봅서의 제작 규칙으로 채택했는가
>
> **V1 원칙:** 새 게임 문법을 발명하기보다, 이미 판매되고 플레이되는 위치기반 게임의 구조를 가능한 한 그대로 참고한다.
> 장소와 이야기 자체가 제주/Odii이므로 1차 차별성은 이미 존재한다고 본다.
>
> 조사 기준일: **2026-09-02**

## 1. 조사 목적

놀멍봅서는 V1에서 “독창적인 게임 시스템을 새로 발명하는 것”을 우선하지 않는다.

우선순위는 다음과 같다.

```text
검증된 위치기반 게임 구조 조사
        ↓
반복되는 제작 문법 추출
        ↓
놀멍봅서에 최대한 그대로 적용
        ↓
제주 장소 + Odii 이야기로 내용 차별화
        ↓
실제 사용자 반응 이후 독자 시스템 확장
```

따라서 콘텐츠 제작 중 판단이 애매하면:

> **내가 새로 상상하기 전에 Questo / Secret City Trails가 어떻게 하는지 먼저 확인한다.**

### 따라할 것

- PLAY의 상품 구조
- 장소별 Game Fantasy와 목표 부여 방식
- 실제 장소를 Challenge로 사용하는 방식
- Mission 수와 플레이 밀도
- Point → Challenge → Story → Next의 진행 구조
- 힌트 / 스킵 / 실패 처리
- 시간·거리·난이도 등 구매 전 정보
- 장소 단서의 안정성 기준
- Creator가 반복 제작할 수 있는 구조

### 그대로 따라하지 않을 것

- 브랜드명, 문구, 캐릭터, 고유 스토리
- 특정 서비스의 저작물인 문제/퍼즐 원문
- 제주 현실과 맞지 않는 억지 퍼즐
- 현실보다 스마트폰 화면에 집중하게 만드는 미니게임

## 2. 핵심 레퍼런스

### 2.1 Questo

**한 줄 정의:** 도시의 실제 장소를 따라 이동하며 위치기반 Puzzle을 풀고 Story를 진행하는 self-guided city game.

2026-09-02 공식 홈페이지 기준:
- **1M+ Explorers**
- **1,075 Cities**
- **3,000+ Quests**
- Quest 가격 **€7.99부터**
- 일반적인 Quest 시간 **1.5~3시간**
- 오프라인 플레이 지원

핵심 구조:

```text
Quest 선택
    ↓
Start Point 이동
    ↓
현실 장소 탐색
    ↓
Location-based Puzzle
    ↓
정답 확인
    ↓
Story / 다음 위치 해금
    ↓
반복
    ↓
Final / Score / Complete
```

Questo 공식 outdoor scavenger hunt 설명에서는 좋은 게임의 핵심을 다음과 같이 설명한다.

- 휴대폰보다 **실제 주변 환경을 보게 한다**
- 건축 디테일
- 명판의 글자
- 건물의 연도
- Street Art
- Historical Marker
- 실제 도시의 흔적

즉 **현실 자체가 Game Board**다.

#### Game Fantasy

Questo는 장소마다 Fantasy를 크게 바꾼다.

예:
- Murder Mystery → 탐정
- Lost Treasure → 보물 추적
- Haunted Quest → 유령/미스터리 추적
- 역사·문화형 → 특정 시대 인물/여정
- Kid Quest → 사건/잃어버린 무언가 복구

하지만 Fantasy가 달라도 핵심 Loop는 유지한다.

> **Story는 변하지만 Game Loop는 반복된다.**

#### Creator 구조

Questo는 현재 **30,000+ creators**를 언급하며 Creator Room에서 다음과 같은 제작 도구를 제공한다고 소개한다.

- GPS waypoints
- Photo challenges
- Riddles
- Timed clues
- 기타 scavenger-hunt challenge

이 점은 장기적으로 놀멍봅서가 Creator Platform으로 확장할 때 중요한 참고점이다.

---

### 2.2 Secret City Trails

**한 줄 정의:** 현실의 작은 디테일을 이용한 location-specific riddle을 풀며 다음 장소와 local story를 해금하는 self-guided discovery walk.

핵심 구조:

```text
Book
 ↓
Start location
 ↓
Riddle
 ↓
도시의 세부 관찰
 ↓
정답
 ↓
다음 위치의 cryptic direction
 + Local Story
 ↓
반복
 ↓
Finish / 기록
```

서비스가 반복적으로 사용하는 핵심:
- notice its details
- sharpen your senses
- hidden details
- unlock local stories
- no AR required

즉 Secret City Trails는 **“평소 보지 않던 것을 보게 한다”**가 제품 정체성에 매우 가깝다.

#### Creator 구조

Creator 모집 페이지에서는 다음을 명시한다.

- 지역을 잘 아는 local creator
- writing
- city secrets
- riddles
- photos
- **coding 불필요**
- Creator가 trail을 계속 active / lively하게 유지
- 제작비 + 판매 revenue share

놀멍봅서의 장기 플랫폼 방향과 특히 가까운 참고점이다.

## 4. PLAY 상품 구조

레퍼런스들은 게임을 시작하기 전에 **얼마나 걷고, 얼마나 걸리고, 몇 개를 풀어야 하는지**를 적극적으로 보여준다.

### 필수 메타데이터

| 정보 | 용도 |
|---|---|
| **PLAY 제목** | Game Fantasy 전달 |
| **장소명** | 실제 관광지 |
| **한 줄 목표** | 이번 PLAY에서 무엇을 해야 하는가 |
| **예상 시간** | 구매/시작 판단 |
| **거리** | 신체 부담 판단 |
| **난이도** | 게임 난이도 판단 |
| **Mission 수** | 플레이 밀도 판단 |
| **Start** | 시작 위치 |
| **Finish** | 종료 위치 |
| **권장 시간대** | daylight / 관람시간 등 |
| **관람 요금** | 별도 입장료 여부 |
| **운영시간** | 시설형 관광지 |
| **주의사항** | 경사·계단·주민공간·종교시설 등 |

## 6. Point와 Mission은 다르다

### Point
**사용자가 실제로 이동해서 도착하는 장소 단위**

### Mission
그 Point에서 수행하는 **현실 기반 행동·발견 단위**

```text
PLAY
├─ Point A
│   ├─ Mission 1
│   ├─ Mission 2
│   └─ Story
│
├─ Point B
│   ├─ Mission 3
│   └─ Story
│
└─ Clear
```

> **Point 수 = Mission 수일 필요가 없다.**

## 7. Mission Pattern Library

중요:

> Mission Pattern은 **현실에서 사용자가 무엇을 하는가**다.
> 버튼/드래그/키패드 같은 UI Input 방식과 구분한다.

### FIND — 찾기
특정 현실 대상을 찾는다.

좋음:
> “비슷한 문 중 하나에만 작은 문이 하나 더 숨어 있다.”

나쁨:
> “호령창을 찾아보세요.”

### COUNT — 세기
특정 특징을 가진 현실 요소의 개수를 센다.

### READ — 읽기
현판·비석·명판·각인·연도 등 문자 정보를 현장에서 찾는다.

### COMPARE — 비교
둘 이상의 현실 대상을 비교해서 차이를 찾는다.

### FOLLOW — 따라가기
조각상의 시선, 손가락, 문양 방향 등 현실 단서를 따라간다.

### ORDER — 순서/배열
현실의 좌우·배열·순서를 읽는다.

### DECODE — 변환/해독
현장에서 얻은 글자·숫자·형태를 간단히 변환한다.

주의:
> 현실보다 암호 자체가 주인공이 되지 않도록 한다.

### INFER — 추론
현실 특징을 관찰한 뒤 용도·이유·관계를 추론한다.

---

## 8. Pattern 조합

좋은 Mission은 Pattern 하나로 끝나지 않을 수 있다.

```text
FOLLOW
 ↓
FIND
 ↓
READ
 ↓
ANSWER
 ↓
STORY
```

또는:

```text
FIND
 ↓
COMPARE
 ↓
INFER
 ↓
STORY
```

> **게임성은 UI 조작 수가 아니라 현실에서 발생하는 사고 단계에서 만든다.**

## 9. Input Method는 별도다

사용 가능한 Input:
- 단일 선택
- 복수 선택
- 숫자 입력
- 짧은 문자열 입력
- 방향 선택
- 순서 배열
- 매칭
- 드래그
- `[찾았어요]`
- Skip

### 객관식
객관식 자체가 나쁜 것이 아니다.

좋음:
```text
현실 조사
→ 단서 확보
→ 추론
→ 객관식 제출
```

나쁨:
```text
설명 읽기
→ 객관식
```

### 자유입력
권장:
- 숫자
- 짧고 명확한 고유 단어

피함:
- 의미가 같은 표현이 여러 개인 답
- 긴 문장
- 철자에 민감한 답

### `[찾았어요]`

가능하면:

```text
FIND
 ↓
[찾았어요]
 ↓
VERIFY 질문
```

을 사용한다.

## 10. Hint / Fail / Skip

### Hint 1 — 방향
**어디를 봐야 하는지**

### Hint 2 — 대상
**무엇을 찾아야 하는지**

### Skip
```text
정답 공개
 ↓
Story 제공
 ↓
계속 진행
```

> Mission 하나 때문에 관광 전체가 막혀서는 안 된다.


> **왜 이 대상을 보게 했는가**

## 12. Game Fantasy

모든 콘텐츠가 강한 역할극일 필요는 없지만, V1에서는 가능하면:

```text
나는 누구인가?
+
이 장소에서 무엇을 완수해야 하는가?
+
Mission을 해결하면 무엇이 누적되는가?
+
마지막에 무엇이 완성되는가?
```

를 만든다.

### 예 — 성읍

**《성읍 생활기록 복원작전》**
- 역할: 기록 복원자
- 목표: 옛 제주집의 생활기록 복원
- 진행: 발견할 때마다 생활기록 추가
- Final: 기록 완성
- CLEAR: 제주집을 보는 새로운 시선 획득

> **모든 장소를 ‘복원’ 게임으로 만들지는 않는다.**

Fantasy 내용은 바꾸되 **역할/목표/진행/완결이 존재한다**는 구조는 유지한다.

---

## 13. Progression

PLAY마다 사용자가:

> **내가 앞으로 가고 있다**

는 걸 볼 수 있게 한다.

가능한 방식:
- 기록 2 / 6
- 단서 4 / 8
- 조각 3 / 5
- 사건 진행도
- 지도 해금
- Chapter 완료

일반적인 XP / Coin보다:
> 이번 PLAY에서 실제로 모으고/해결하는 것이 무엇인가
를 보여주는 방식을 우선한다.

---

## 14. CLEAR

마지막은 “문제를 다 풀었습니다”로 끝내지 않는다.

```text
Mission 1~N
 ↓
발견 누적
 ↓
Final
 ↓
전체 의미 연결
 ↓
CLEAR
```

좋은 CLEAR는 사용자가 Mission에서 얻은 발견이 **하나의 결과로 완성**되는 것이다.

## 15. 실제 서비스에서 확인되는 실패 패턴

### 현실 단서가 사라짐
- 조형물 제거
- 안내판 교체
- 전시 변경
- 공사

대응:
- 움직이지 않는 건축/문화재 요소 우선
- 최근 자료 확인
- Skip 가능
- Point를 독립 데이터로 관리

### 접근 불가
- 공사
- 폐쇄
- 영업시간
- 행사
- 종교/주민 공간

대응:
- 운영시간
- 입장료
- 접근제한
- daylight 조건 확인

### 정답 검증이 너무 엄격함
대응:
- 자유입력 최소화
- 의미 추론은 선택/매칭
- 필요 시 여러 정답 variant

### 단서가 애매함
대응:
- 한정된 관찰 범위
- 명확한 특징
- 하나의 답
- 단계별 Hint

### 퍼즐과 장소가 따로 놂
질문:
> **이 Mission은 이 장소가 아니면 성립하지 않는가?**

NO라면 우선 제거한다.

## 18. 놀멍봅서에서 최대한 따라갈 기본값

### 상품
- Self-guided
- Start anytime
- Pause / Resume
- 시간 / 거리 / 난이도 / Mission 수 사전 표시

### PLAY
- 장소별 Game Fantasy
- 역할 + 목표
- 약 45~90분 우선 검토
- 약 8~12 Mission
- Mission 진행도 표시
- Final + CLEAR

### Mission
- 현실 단서 우선
- 위치 특화
- 관찰 먼저
- Story 나중
- FIND / COUNT / READ / COMPARE / FOLLOW / ORDER / DECODE / INFER에서 우선 선택
- UI 미니게임을 억지로 발명하지 않음

### Story
- Mission 해결 뒤 해금
- Odii 사용
- 발견과 직접 관련된 부분 우선

### 실패
- Hint 2단계
- Skip
- 진행 차단 금지

## 19. 레퍼런스와 놀멍봅서의 차이

V1에서는 차별화를 위해 새로운 Game Mechanic을 억지로 추가하지 않는다.

이미 다음 차이가 존재한다.

### 장소
**제주 관광지**

### Story 공급원
**한국관광공사 Odii**

### 콘텐츠 방향
> **제주의 실제 문화·역사·생활 디테일을 직접 발견하고 그 뒤 공식 이야기를 듣는 구조**

따라서 V1 전략은:

> **게임 문법은 최대한 레퍼런스를 따라가고, 내용은 제주가 차별화한다.**

사용자 반응과 운영 데이터가 쌓인 뒤 놀멍봅서만의 Mechanic을 추가한다.

## 20. 문서 사용 규칙

콘텐츠를 만들 때 판단 우선순위:

```text
1. 실제 장소의 현실
2. Odii 원문
3. 이 레퍼런스 문서의 검증된 문법
4. 콘텐츠.md의 놀멍봅서 규칙
5. 새 아이디어
```

새 아이디어는 **레퍼런스 문법으로 해결할 수 없을 때만** 추가한다.

Top 5에서 반복해서 유효성이 확인된 경우에만 `콘텐츠.md`의 공통 규칙으로 승격한다.
