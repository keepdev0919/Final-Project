## 0. 왜 또 피벗했나

v1의 축은 **"현장 참여형 AI 스토리 경험"** 이었다. 조익준님이 08-14 세션에서 이 축의 병목을 짚었다.

> *"투어라이브는 유명한 사람들이 자기 콘텐츠를 올리고 그걸 구매하는 거라, 그 장소 맥락을 알고 지식이 있는 사람이 진행하는 콘텐츠인데, 우리 구조는 내가 그걸 구상해야 되잖아. 그래서 경쟁력이 떨어진다고 생각이 들어서."*

**진단이 정확했다.** v1의 진짜 병목은 기술이 아니라 콘텐츠였고, 그 콘텐츠를 개발자 1명이 전문가 수준으로 써야 했다. 성산 하나에 몇 주가 들고, 다 쓰고 나서 "이게 5,000원짜리인가"를 검증할 방법도 없었다. 40일 마감에서 이건 실제 위험이었다.

**두 개의 해법이 동시에 나왔다.**

1. **콘텐츠를 우리가 쓰지 않는다** — 한국관광공사 **오디(Odii) OpenAPI**가 제주에 224곳의 오디오 해설을 제공한다. 대본·좌표·재생시간·한국어/영어까지. (v1 시점에는 이 API가 "500 오류, 사용 불가"로 잘못 기록돼 있었다. 08-14에 엔드포인트를 바로잡고 실호출로 검증했다 → `docs/kto-api/kto-apis.md` §7)
2. **파는 것을 바꾼다** — "깊은 해설"이 아니라 **"그 장소에서 하는 놀이"**. 해설은 그 안에 들어가는 재료가 된다.

### 이 피벗이 해결하는 것

| v1의 문제 | v2 |
|---|---|
| 원고를 개발자가 다 써야 함 | 관광공사가 이미 쓴 224건을 쓴다 |
| 성산 1개 완성에 몇 주 | 제주 전역이 첫날부터 채워짐 |
| "오디와 뭐가 다른가"에 약한 답 | **오디는 듣는 앱, 우리는 하는 앱** |
| 유료 축에 KTO 데이터가 없음 | 유료 축 한복판이 KTO 데이터 |
| 외국인 대상이면 원고를 다시 씀 | `langCode=en`으로 영어가 그냥 나옴 |

## 1. 제품 정의

**놀멍봅서** — 제주어 "천천히 보세요".

> **제주의 관광지에서, 눈앞의 실제 사물을 찾아 수집하는 위치 기반 퀘스트 게임.**

- **누가:** 제주에 온(또는 올) 여행자.
  > **⚠️ 2026-08-15 정정.** 이 자리에 원래 *"이미 숙소와 일정을 정하고 도착한 여행자. 여행 계획은 우리 영역이 아니다"* 라고 적혀 있었다. **철회한다.** 코스를 되살리기로 했기 때문이다(§7). 다만 **일정을 짜주는 앱이 되겠다는 뜻은 아니다** — 우리가 하는 건 검증된 코스를 **골라서 보여주고**, 그 코스 위의 장소로 데려가는 것까지다. 일정 편집·저장 기능으로 번지지 않는다.
- **언제:** 관광지에 **도착한 순간부터**.
- **무엇을:** 그 장소를 걸으며 지점을 찾고, 실제로 존재하는 것을 수집하고, 왜 그런지를 듣는다.
- **왜 돈을 내나:** 무료로도 해설은 다 들을 수 있다. **돈을 내면 그 장소가 "놀이"가 된다** — 지점 경로, 수집, 보스, 기록.

### 북극성 (v1에서 교체)

> **v1:** 폰을 적게 보게 한다 — *게임으로 가면서 폐기*
> **v2:** **앱이 사람을 그 자리에 서서, 실제로 그것을 보게 만든다.**

포켓몬고의 실패는 사람들이 장소에 가서 **화면만 본 것**이다. 우리가 **수집물을 가상 몬스터가 아니라 실물로** 정한 것이 이걸 막는다. 일출을 얻으려면 일출을 봐야 하고, 해식동굴을 얻으려면 절벽을 봐야 한다.

**이 북극성이 지키는 것 셋**
1. 수집물은 그 장소에 실제로 있는 것에서 나온다
2. 걷지 않고 얻는 것은 없다
3. 화면은 도착·수집 순간에만 짧게 본다 — 걸으면서 보게 만들지 않는다 (안전 문제이기도 하다)

### 오디와 무엇이 다른가 (기능설명서 6번의 답)

> **오디는 듣는 앱이고, 우리는 하는 앱입니다. 오디의 해설을 현장에서 몸으로 하는 활동으로 바꿉니다.**

v1의 답("우리도 이야기를 하는데 좀 더 반응형이다")은 주최측 앱과 **같은 링에 올라간 경쟁자**였다. v2의 답은 우리를 **오디를 더 쓰게 만드는 쪽**에 세운다. 주최측이 심사하는 공모전에서 이 차이는 크다.

## 2. 콘텐츠 공급 구조

### 두 층으로 나눈다

| | **오디오 지점** (무료) | **퀘스트** (유료) |
|---|---|---|
| 개수 | 약 180곳 | **출시 시점 5~10개** |
| 출처 | 오디 OpenAPI 실시간 호출 | 오디 대본 + 서칭 + 창작 |
| 우리 작업량 | **0** | 장소당 1~2일 |
| 지도 표시 | 작게 · 연하게 | 크게 · 진하게 · 배지 |
| 누르면 | 그 장소 해설 재생 | 퀘스트 시작 |
| 리뷰 | 안 받음 | **받음** ← 콘텐츠 디벨롭용 |
| 조익준님이 관리 | **0개** | 5~10개 |

**"준비중"으로 막지 않는 이유.** 지도에 뜨는 189개 핀(대본 없는 35건 제외) 중 5~10개만 열려 있고 나머지가 "준비중"이면 사용자는 20번 눌러 19번 실망한다. 심사위원도 같은 경험을 한다. 대신 **관광공사 해설을 그대로 들려주면** 누를 때마다 뭔가를 얻는다. 그리고 그건 우리가 만들 것도 고칠 것도 없다.

**부수 효과 — 공모전 자격 요건이 뒤집힌다.** 180곳을 누를 때마다 오디 OpenAPI를 실시간 호출하게 되므로 호출 이력이 대량으로 쌓인다. 공지가 경고한 *"개발 기간 내 API 호출 이력이 확인되지 않을 경우 심사 불이익"* 이 정반대가 된다.

### 오디 데이터 실측 (2026-08-14)

`http://apis.data.go.kr/B551011/Odii/storyLocationBasedList` · `langCode` 필수

| | 한국어 | 영어 |
|---|---|---|
| 전국 | 6,538건 | 4,538건 |
| **제주** | **224건** | 130건 |

받는 필드: `title, audioTitle, script(대본 전문), audioUrl, imageUrl, mapX, mapY, playTime, langCode`

**⚠️ 세 가지 제약**
1. **오디오 파일은 47건(21%)뿐이다.** 나머지는 대본만 있다 → TTS로 읽는다. 그러면 "오디 음성을 트는 것"이 아니라 "오디 대본을 우리가 읽는 것"이 되므로 **저작권 판단이 달라진다. 주최측 확인 필요.**
2. **대본이 없는 건이 35건** 있다 (제목만). 이건 지도에도 표시하지 않는다.
3. **장소당 이야기 1개다.** 성산 반경 3km에 2건뿐. 지점별로 쪼개져 있지 않다.

### 무엇을 저장하고 무엇을 실시간으로 부르나 (2026-08-19 결정 · 구현 완료)

기준은 **"바뀌느냐"** 하나다.

| 로컬에 저장 (안 바뀌는 뼈대) | 실시간 호출 (바뀌는 내용물) |
|---|---|
| 오디 224곳 목록 — `stid`·제목·좌표·재생시간 | **오디 대본·음성** ← 재생 버튼 누를 때 |
| 우리가 정한 것 — 코스 n개, 홈 순위 | KorService2 **운영시간·휴무·입장료·전화·개요·사진** ← 장소 화면 열 때 |

**대본(`script`)은 저장하지 않는다.** 있는지 여부(`has_script`)만 둔다. 이유 둘 —
① 관광공사 콘텐츠를 쟁여두고 재배포하는 모양을 피한다(오디오 파일이 21%뿐이라
TTS 저작권 판단이 아직 미결이다 → §9). ② 공지가 *"로컬 DB 저장이 아닌 실시간
호출을 강력히 권고, 개발 기간 내 호출 이력이 없으면 심사 불이익"* 을 명시했다.
**재생이 곧 호출이 되게** 만든다.

**호출이 생기는 지점**

```
지도·홈 열기        → 0건   (로컬 목록)
장소 화면 열기      → 3건   (개요·운영시간·사진)
오디오 재생 누르기  → 1건   (대본·음성)
목록 주기 갱신      → 7일에 1건
```

**좌표를 서버로 보내지 않는다.** `/odii/story`는 `stid`만 받고 좌표는 서버가
저장된 목록에서 꺼낸다. 코스 장소 ↔ 오디 장소 매칭도 앱이 단말에서 거리로 한다.
클라이언트가 좌표를 보내는 구조로 두면 나중에 "내 주변 해설 듣기"를 붙이며
사용자 위치가 넘어가고, 그 순간 위치기반서비스사업자 신고 대상이 된다.

**구현된 것 (2026-08-19)** — `backend/routers/odii.py`
`GET /odii/places` (로컬 목록, 대본 있는 189곳) · `GET /odii/story?stid=` (실시간) ·
`POST /odii/sync` (목록 갱신). 고정 테스트 `tests/test_odii.py`.

### 음성은 우리가 만든다 — 안 D (2026-08-20 결정 · 구현 완료)

**오디가 주는 음성 파일을 쓰지 않는다.** 189곳 중 47곳(21%)에만 있어서, 섞어 쓰면
장소마다 목소리가 바뀐다. **대본만 받아 전부 우리 TTS로 통일한다.**

| | |
|---|---|
| 플랫폼 | **Typecast** `ssfm-v30` (감정 프리셋 7종 · 캐릭터 목소리 590종) |
| 곱닥이 목소리 | `tc_63edf3ccd8e2eb7338999376` **Mirei Kato** (female/child) — 후보 3명 비교 후 선택 |
| 요금 | 글자당 1 크레딧. 라이트 $15/월 = 20만 크레딧 |

**왜 Typecast인가.** OpenAI는 범용 목소리 11개뿐이라 픽셀아트 가이드 캐릭터에 맞는
목소리가 없었다. Typecast는 캐릭터 목소리와 `whisper` 같은 감정 프리셋을 준다
(절·유적지에서 톤을 낮출 수 있다).

#### 왜 캐시하나 — 실측이 결정했다

같은 대본·같은 목소리면 결과가 **항상 같다.** 그런데 재생마다 생성하면 비용이
사용자 수에 비례한다. 189곳 총 22,443초를 글자로 환산(실측 6.4자/초)해 계산했다.

| | 월 크레딧 | 비용 |
|---|---|---|
| **안 C** 매 재생마다 생성 (하루 20명 × 5곳) | 228만 | **$202/월** |
| **안 C** 하루 200명 | 2,280만 | **$2,049/월** |
| **안 D** 장소당 1번 (189곳 전체 1회) | 14만 | **$15 한 번** |

**안 C는 경제적으로 불가능하다.** 안 D로 간다.

#### 대본은 여전히 저장하지 않는다

캐시 키는 **대본의 SHA-256 해시**다. `tts_cache` 테이블에 대본을 담는 칸이 없다
(`tests/test_tts.py`가 이걸 감시한다). 08-19 결정("대본을 저장하지 않는다")을
문자 그대로 지키면서 생성 비용만 줄인다. 대본이 바뀌면 해시가 달라져 자동으로
다시 만들어진다.

#### 호출 흐름

```
재생 버튼 → GET /odii/story?stid=   KTO 실시간 호출 (호출 이력 남음)
                                    대본을 자막으로 뿌린다
          → GET /tts/odii?stid=     대본 해시로 캐시를 찾는다
                                    히트 → 파일 스트리밍, Typecast 0회
                                    미스 → 생성 후 저장
```

**⚠️ 첫 생성은 20초 걸린다** (1,039자 실측). 캐시 히트는 0.0초다. 그래서
**출시 전에 189곳을 배치로 미리 생성해 캐시를 채워둬야 한다.** 사용자가 20초를
기다리는 경로가 남아 있으면 안 된다. 라이트 플랜 한 달로 한 번에 만든다.

**⚠️ 남은 문제는 KTO 한도다.** TTS는 캐시로 풀렸지만 대본 호출은 재생마다 나간다.
개발계정 일 1,000건이면 하루 200명에서 막힌다. 운영계정 신청은 **출시 전에
조익준님이 직접** 한다 (출시 전까지 사용자가 없어 급하지 않다 — 08-20 결정).

### 이미 지점이 나뉜 묶음 — 45건(20%)

**여기가 이 피벗의 핵심 발견이다.** 아래 8묶음은 오디 데이터가 **이미 한 장소를 여러 지점으로 쪼개 놓았다.** 그대로 다지점 퀘스트 경로가 된다.

| 묶음 | 지점 | 오디오 길이 |
|---|---|---|
| **관음사** | 10 | 7분 |
| **약천사** | 7 | 7분 |
| 서귀포 예술 기행 | 6 | 10분 |
| 안도 코스 (섭지코지 일대) | 6 | 9분 |
| **제주 성읍마을 고택** | 5 | 8분 |
| 이중섭의 행복길 | 4 | 6분 |
| 이타미 코스 | 4 | 6분 |
| 성안올레 | 3 | 대본 없음 — 제외 |

관음사: *일주문 → 사천왕문 → 대웅전 → 미륵대불 → 방사탑 → 범종각 → 삼성각 → 지장전 → 나한전 → 해월굴*

**8묶음이 전부 "걸어서 도는 곳"이다** — 절, 민속마을, 도심 예술 코스, 리조트 단지. 넓은 산·해안이 아니라 5~10분 안에 지점들이 붙어 있어 **GPS 퀘스트에 가장 잘 맞는 지형**이다.

| **홈** | 오디 제공 장소를 **인기도순**으로. 장소 콘텐츠 소개가 중심 |
| **탐험** | **루트 선택** — 선별한 코스 n개. 난이도·소요시간·거쳐가는 장소 |
| **지도** | 오디 189곳 + 내 위치 + 선택한 루트 경로 |
| **내 것** | 구매한 퀘스트 · 수집한 것 · 진행도 · **구매 복원** · 로그인 · 언어 · **계정 삭제** · 출처 표기 |

> **변경 이력.** 08-14 초안은 5개(홈·검색·여행지도·나의 콘텐츠·프로필)였다.
> **검색**은 뺐다 — 장소가 189곳이라 전용 탭이 아깝다(지도와 홈 상단에 붙인다).
> **프로필은 "내 것"에 합쳤다** — 지금 단계에서 프로필 단독 탭을 채울 내용이 없다.
> 나중에 수집물·업적이 쌓여 "내 것"이 무거워지면 그때 다시 나눈다.

**지도를 별도 탭으로 둔 이유.** 현장에서 가장 자주 하는 행동이 *"지금 내 주변에 뭐 있지"* 인데, 그게 두 번 눌러야 나오면 안 된다. 탐험 탭 안에 넣는 안은 기각했다.

**⚠️ "내 것" 탭 안에 이 둘이 반드시 있어야 한다** — **구매 복원**(유료 콘텐츠 앱 필수)과 **계정 삭제**(로그인 있는 앱 필수). 탭을 합쳤다고 경로가 사라지면 앱스토어에서 거절된다.

### 루트 카드 (탐험 탭)

```
해안 올레길
느긋 · 하루 12km · 예상 4~5시간 · 오디오 5곳
[ 루트 선택 ]
```

**난이도는 하루 이동거리로 정한다** (2026-08-20 결정). 목업에 있던 "레벨 40+"는 **뺀다** — 그 값을 만들 데이터가 없다.

| 표기 | 기준 |
|---|---|
| 여유 | 하루 16km 미만 |
| 보통 | 16~32km |
| 강행군 | 32km 이상 |

**루트 이름과 설명 두 줄은 조익준님이 직접 쓴다.** 자동 생성하지 않는다 — 코스 최종 선별을 사람이 하기로 한 것(§7)과 같은 이유다.

### 투어라이브에서 **가져오지 않는** 것

`★4.9 (215)` · `실시간 구매 현황 LIVE` · `실시간 후기` — **판매자와 구매자가 많을 때만 작동하는 화면이다.** 출시일에 우리는 리뷰 0개, 구매 0건이다. 별점이 비고 실시간 목록이 텅 빈 화면은 **죽은 앱처럼 보이고**, 심사위원이 그걸 본다.

→ 그 자리는 데이터로 채운다: **"내 주변 3km에 5곳"**, **"오늘 열린 퀘스트"**.
→ 리뷰가 쌓이면 그때 켠다.

### 상품 카드 — 사람 이름 자리에 게임 정보

투어라이브는 유명인 IP로 40,000원을 받는다(*"100만 유튜버 코미꼬와 함께하는"*). **우리에겐 그 이름이 없다.** 그 자리를 게임 정보가 대신한다.

```
관음사 — 일주문에서 해월굴까지
4,900원 · 지점 10곳 · 배지 3종 · 약 40분 (걷는 시간 포함)
```

**⚠️ "소요시간"은 걷는 시간을 포함해 쓴다.** 관음사 오디오 합계는 7분이지만 실제로는 40분쯤 걸린다. 7분이라고 쓰면 현장에서 배신감이 든다.

## 4. 퀘스트 런타임

### 흐름

```
[집/숙소]  홈 또는 지도 → 퀘스트 카드 → 소개 화면
           · 지점 몇 개 / 몇 분 / 어디서 시작 / 무엇을 모으나
           · [미리 듣기]  [미리 받아두기]

[도착]     GPS가 장소 진입을 감지 → "지금 여기예요" → 퀘스트 시작

[지점]     지점 반경 진입 → 자동 재생 (설정에서 끌 수 있고, 수동 재생도 됨)

           ┌────────────────────────┐
           │  [ 장소 픽셀 풍경화 ]      │  ← 고정 배경
           │                        │
           │ ┌────────────────────┐ │
           │ │[곱닥이] 약 5천년 전, │ │  ← 대화 상자
           │ │ 지하에 있던 마그마가_│ │     음성에 맞춰 타자기
           │ └────────────────────┘ │
           │  [질문하기]   [다음]     │
           └────────────────────────┘

[수집]     지점에서 실물을 얻는다 → 도트 아이템이 뜬다
[보스]     핵심 지점(정상 등)에서 연출 있는 수집
[완료]     들은 것·모은 것 기록 화면 (픽셀아트) → 리뷰 요청
```

### 대화 상자 — 오디오가 주인, 글자는 자막

말하는 속도에 맞춰 글자가 찍힌다. **세 상황을 한 화면으로 덮는다.**

| 상황 | 사용자 |
|---|---|
| 이어폰 끼고 풍경 봄 | 화면 안 봄. 소리만 |
| 시끄럽거나 이어폰 없음 | 글자를 읽음 |
| 나중에 다시 봄 | 전문이 남아 있음 |

**필수 넷**
1. **화면을 꺼도 계속 재생된다.** 잠금화면·이어폰 버튼으로 재생/정지/다음. (`UIBackgroundModes: audio`는 이미 설정돼 있다)
2. **탭하면 전문이 즉시 나온다.** 게임의 관례. 없으면 읽는 사람이 답답하다.
3. **글자 속도는 음성이 정한다.** 음성이 없는 곳에서만 타자기가 자체 속도를 갖는다.
4. **긴 글은 픽셀 폰트를 쓰지 않는다** (`DESIGN.md` §3). 대본 전문은 시스템 폰트.

### 배경 — 장소별 픽셀 풍경화 (2026-08-14 결정)

정지된 그림 한 장이라 게임 화면처럼 주의를 끌지 않고, 타자가 찍히는 화면에 바탕은 필요하다.

**참고사진(실사)은 별도 버튼으로 남긴다.** 배경이 그림이어도 *"정면 저 검은 구멍들을 보세요"* 를 짚으려면 실사가 필요하다. 상단 오른쪽에 둔다.

### 실패 처리 — 퀘스트는 멈추지 않는다

| 상황 | 동작 |
|---|---|
| GPS 미수신·오차 | 수동 재생. "여기 맞아요" 자기보고 버튼 |
| 통신 없음 | 미리 받아둔 대본·오디오·그림으로 계속 |
| 미다운로드 + 통신 없음 | "와이파이에서 미리 받아주세요". 시작 전 다운로드를 강하게 권유 |
| 오디 API 실패 | 캐시된 대본으로 진행. 사용자는 실패를 모른다 |
| 앱 종료 후 재시작 | 진행 위치 복원 |

> **원칙: 수집·연출이 실패해도 걷고 듣는 것은 끝까지 된다.** 심사 배점의 "안정성"에 직결된다.

### GPS

- 지점 반경 **40m**, 체류 조건 없음
- **iOS 지오펜스는 앱당 20개 상한.** 가까운 지점만 등록하고 멀어지면 해제한다
- **사용자 위치를 서버로 보내지 않는다.** 판정은 단말에서만 (위치정보법 · 단계 0에서 세운 불변식)

## 5. 수익 모델

**단건 + 올패스 병행** (투어라이브도 "파리 올패스"처럼 도시 단위 패스를 판다).

| | 단건 | 제주 올패스 |
|---|---|---|
| 범위 | 퀘스트 1개 | 열린 퀘스트 전부 + 이후 추가분 |
| 가격 | **4,900원** (잠정) | **19,900원** (잠정) |
| 기간 | 90일 | 90일 |

**⚠️ 가격은 조익준님이 정하실 항목이다.** 위 숫자는 자리표시이며, 확정 전까지 어떤 문서도 이걸 확정으로 적지 않는다.

- 애플 **비갱신 구독(Non-Renewing Subscription)** — 기간이 있는 1회 구매
- 이용 기간은 **우리 서버가 기록한다** (Firebase Auth + Firestore)
- 디지털 콘텐츠이므로 외부 결제 수단을 넣으면 거절된다
- **구매 복원 버튼 필수** · 기간 만료 표시 · 재구매 경로

**올패스로 유도하는 이유.** 여행자는 3~5일 머문다. 갈 때마다 결제 화면을 만나면 짜증나고, 많이 돌수록 이득인 구조가 여러 장소로 가게 만든다 — 관광 활성화라는 심사 취지에도 맞는다.

### 심사위원 접근

지정 형식 계정(`openapi`)으로 로그인하면 **올패스가 열린 상태**여야 한다. 계정 정보는 이 문서에 적지 않는다 — `_심사요약.md`와 `.env`에만 둔다.

## 7. 버리는 것

| 대상 | 이유 |
|---|---|
| **설화** | 08-14 기준 코드는 이미 제거 완료 |

### ⛔ 철회 — 코스는 버리지 않는다 (2026-08-15 조익준님 결정)

원래 이 자리에 **코스 추천·취향 퀴즈·내 코스를 전부 버린다**고 적혀 있었다(08-14). **철회한다. 코드는 하나도 지우지 않았으므로 잃은 것은 없다.**

철회 이유 — 08-14 판에는 **"사용자가 이 앱을 처음 어떻게 열게 되는가"** 가 비어 있었다. "이미 도착한 사람"만 상대하겠다고 잘라놓으면, 도착하기 전에 앱을 깔 이유가 없다. 코스가 그 입구다: 코스를 보다가 → 지도에서 장소를 만나고 → 그 장소에 콘텐츠가 있으면 듣고 → 나중에 그 장소가 퀘스트가 된다.

**되살리는 것** — `/course/*` · `course_list_agent` · `course_detail_agent` · `CourseHubView` · `CourseListView` · `CoursePreviewView` · `MyCourseListView` · `TasteDiscoveryView` · `SavedCourse` 및 저장·동기화.

**단, 커지지 않게 막는 선:** 일정 편집기·직접 코스 만들기로 번지지 않는다. 우리가 하는 건 **이미 검증된 코스를 골라서 보여주는 것**까지다.

### ⚠️ 코스 화면을 만들 때 밟을 함정 — 제목으로 조회하지 마라 (2026-08-20 확인)

`curated_courses.origin_title`은 **비짓제주 사용자가 쓴 개인 메모**다 — `"여행"`, `"^^"`, `"제주도"`.
**유일하지 않다.** 이 값으로 `courses`를 역조회하면 남의 코스가 통째로 딸려온다.

```
curated.title = courses.title          →   0곳
curated.origin_title = courses.title   → 891곳   ← id=19670 "전체 3일 · 천왕사 외 10곳"
course_places WHERE course_id = 19670  →  12곳   ← 정답
```

**현재 백엔드는 깨끗하다** (08-20 확인). `/course/list`·`/course/detail`·`/home/recommendations`·
`get_places_for_course()` 전부 `course_id`로 조회한다. 함정은 코드가 아니라 **데이터**에 있고,
탐험 화면을 만들며 누가 제목으로 조회하는 순간 터진다.

→ `tests/test_course.py::test_course_places_are_looked_up_by_id`가 이걸 막는다.

### 만드는 순서 — 무료층 먼저 (2026-08-15 조익준님 결정)

**유료 퀘스트는 지금 구체화하지 않는다.** 무료층(코스·홈·지도·오디 재생)을 먼저 다 만들고, 그 위에 퀘스트를 얹는다.

순서를 이렇게 잡는 이유는, 무료층이 **퀘스트가 올라앉을 바닥**이기 때문이다. 지도·GPS·오디오 재생·장소 상세는 퀘스트에서 그대로 다시 쓴다. 바닥을 먼저 깔면 퀘스트는 그 위에 규칙(지점 순서·수집·배지)만 얹는 일이 된다. 반대로 하면 두 번 만든다.

**지금 만드는 것 (무료층)**

```
[홈]     오디 제공 장소 중 중요도순 n개를 위에서 아래로
           ↓
[코스]   엑기스 n개 코스 · 필터로 좁히기
           ↓ 코스 누름
[지도]   제주도 지도에 그 코스의 루트  ← 이미 구현됨, UI만 다듬음
         루트 위 장소 중 오디에 있는 곳 = 핀·썸네일 표시
           ↓ 핀 누름
[장소]   오디에 있는 곳  → 오디 대본·오디오를 그대로 재생 (실시간 호출)
         오디에 없는 곳(식당 등) → 기존 장소 상세 로직 그대로
```

**그다음 (유료층)** — 위 장소들 중 5~10곳을 골라 퀘스트로 만든다. §2~§6이 그 설계다.

**조익준님 작업** — 비짓제주 코스 약 9,000개를 직접 보고 **쓸 만한 n개로 추린다.** 지금 `build_curated_courses.py`의 자동 점수(경로 효율·장소 수·관광지 비율)는 사람 눈을 대신하지 못한다. 자동 점수는 후보를 줄이는 데까지만 쓰고, 최종 선별은 사람이 한다.

**아직 안 정해진 것 → §8**

**데이터는 지우지 않는다.** `VISIT JEJU CSV`·지오코딩 결과·설화 원본·벡터DB는 남긴다. 코드만 걷어낸다. 나중에 "이 근처에 사람들이 실제로 많이 간 곳" 같은 걸로 쓸 여지가 있고, 벡터DB는 git에 없어 복구가 불가능하다.

**되살아나는 것:** 단계 0에서 진입 경로만 사라진 채 보존해 둔 **리뷰 기능**(`POST /place/review` · `PlaceReviewSheet` · 음성 받아쓰기)이 퀘스트 완료 화면에 붙는다.
