## 1. 프로젝트 목표

> 2026년 9월 10일까지 **애플 앱스토어에 등록 완료**된 iOS 앱

**서비스 한 줄 정의**

**핵심 사용자** — 제주에 온(또는 올) 여행자. 특히 **일정을 아직 확정하지 않은 소규모 여행자.**

**사용자가 해결하는 문제**
1. 제주에 뭐가 있는지는 알지만 **어떤 순서로 묶어야 하는지**를 모른다 → 실제 여행자 9,134명의 일정에서 고른다
2. 관광지에 도착했는데 **안내판 몇 줄이 전부**다 → 그 자리에서 해설이 재생된다

**핵심 플로우** (2026-08-22 갱신 — 입구가 둘이다)
```
[한 곳씩]  홈 장소 카드 10곳 (또는 지도 핀) → 장소 상세 = 퀘스트 소개
           → 현장 도착 → GPS 감지 → 해설 재생 → 지점이 여럿이면 [다음] → 기록

[이은 길]  코스 탭 → 지역·일수 입력 → 실제 여행자 루트 목록 → 루트 선택
           → 루트 상세 → 그 안의 장소를 누르면 위 흐름으로 들어간다
```

## 2. 탭 구조 🔒 (2026-08-22 재확정)

| 탭 | 하는 일 | 겹치지 않는 근거 |
|---|---|---|
| **홈** | 제주 대표 장소 **카드 10곳** → 누르면 장소 상세(=퀘스트 소개) | 앱의 입구. **한 곳씩** 고르는 자리 |
| **코스** | 지역·일수 → 실제 여행자 루트 목록 → 루트 상세 · 내 코스 | 여러 곳을 **이은 길** |

| **프로필** | 다녀온 곳·저장한 루트·로그인 | — |

> **「탐험」 탭을 없앤다.** 거기 있던 「준비된 이야기」 목록이 홈의 장소 카드와 같은 것이었다.
> 퀘스트는 별도 탭을 만들지 않는다 — **장소를 누르면 나오는 상세 화면이 곧 퀘스트 소개다**(§3 P0-5).

### 08-20 결정에서 뒤집힌 것 — "홈에 목록을 두지 않는다"

08-20에는 *"홈에 목록을 두면 반드시 다른 탭과 겹친다"* 며 홈을 "지금 뭘 할 차례" 하나로 잡고,
장소 목록은 「탐험」 탭에 뒀다. **08-22에 반대로 정했다 — 목록을 홈에 두고 탐험 탭을 없앤다.**

뒤집은 이유: 겹침을 없애는 방법이 두 가지였는데 08-20에 고른 쪽이 탭을 하나 더 쓰는 쪽이었다.
목록을 홈에 두면 **탭이 하나 줄고 겹침도 사라진다.** 홈이 "지금 뭘 할 차례"만 보여주는 안은
아직 다녀온 데이터가 없는 첫 사용자에게 빈 화면이 되는 문제도 있었다.
남는 20일 안에서 만들 화면 수를 줄이는 판단이기도 하다.
