## B. 남은 작업 — 우선순위 순

### 1. 🔴 배포 DB 문제 — 이걸 풀지 않으면 배포해도 빈 앱이 뜬다

`storage/metadata.db`(19MB)가 **`.gitignore:11`로 제외**되어 있다. Railway는 git에서 배포하므로
서버는 뜨지만 **퀘스트·코스·지도가 전부 빈 화면**이 된다. 심사관에게는 "동작하지 않는 앱"이다.

이 파일에 든 것: `curated_courses` 1,255 · `home_places` 121 · `odii_places` 224 ·
`courses` 9,134 · `course_places` 146,508.

- 가장 빠른 길: `.gitignore`에서 빼고 커밋 (19MB는 GitHub 100MB 제한에 여유롭다)
- 커밋 전 확인: `place_reviews`(2건)·`mission_reports`(1건)에 든 값이 공개돼도 되는지
- 대안: Railway Volume을 붙이고 파일을 따로 올린다 — 더 깔끔하지만 시간이 더 든다

### 2. 🔴 Railway 배포

- 배포 설정 파일이 하나도 없다 (`Dockerfile`·`Procfile`·`railway.json`·`nixpacks.toml` 전부 없음)
- FastAPI 진입점은 `backend/main.py`의 `app`. Railway가 주는 `PORT` 환경변수를 써야 한다
- 환경변수 이전 필요: `KTO_API_KEY`(64자, 디코딩키) 및 Typecast 키 등 `.env` 항목
- 배포 후 `Config.baseURL`의 릴리즈 값을 **죽어 있는 `https://api.jejufolklore.com`에서 새 주소로 교체**
- 확인: `https://<새주소>/privacy` 가 브라우저에서 열릴 것

### 3. 🟡 코스 자동 도착 감지 제거 (사용자 승인 완료, 2026-09-09)

`ExploreView`는 `CoursePreviewView`(지도 + 일자별 장소 목록 + 장소 상세)를 거의 그대로 복제한 뒤
GPS 자동 체크만 얹은 중복 화면이다. 제거하면 코스 흐름이 **추천 → 미리보기 → 장소 상세(KTO)** 로 단순해진다.

제거 근거: 도착 시 보내는 푸시 문구가 *"준비된 이야기를 들어보세요"* 인데 **그 이야기 기능은
2026-08-13에 제거됐다.** 없는 기능을 가리키는 알림이 심사관에게 노출된다. 알림 권한 요청도 함께 사라진다.

- 진입점: `CoursePreviewView.swift:65-70`, `MyCourseListView.swift:201`, `ContentView.swift:126`
- 딸린 것: `ExploreViewModel`, `ArrivalOverlayView`, `TravelSession`/`TravelStore`, `.exploreDidComplete` 알림
- ⚠️ **`LocationService`는 지우지 말 것** — 현장 PLAY의 거리 표시에 쓰인다. 코스 탐험용 API만 걷어낼 것
- ⚠️ `PlaceReviewSheet`·`SpeechRecognizer`·`backend/routers/review.py`는 `ExploreView.swift:89-97` 주석대로
  **되살릴 예정이니 지우지 말 것**

### 4. 🟡 스토어 제출 실무

`docs/store/앱스토어-등록정보.md`에 앱 이름·설명·키워드·심사 메모 원고가 준비돼 있다. 그중 필수 확인:

- **심사 메모를 반드시 넣을 것.** 심사관은 제주에 오지 않는다. 「도착했어요」와 「건너뛰기」로
  현장 없이 완주까지 확인하는 방법을 적어야 Guideline 2.1 리젝을 피한다
- 처리방침의 **문의 이메일** 빈칸 채우기 (`backend/static/privacy.html`)
- 스크린샷 6.9인치 3~5장 — **서버 배포 후** 촬영해야 실제 데이터가 담긴다
- 앱 아이콘 1024는 이미 있음 (`AppIcon-1024.png` 외 dark/tinted)
