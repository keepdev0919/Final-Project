# 단계 0 — 제출 가능한 상태 만들기 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 콘텐츠와 무관하게, 앱스토어 심사에서 거절될 사유와 공모전 자격 요건 위험을 선제적으로 제거해 "언제든 제출할 수 있는" 코드 상태를 만든다.

**Architecture:** 기존 FastAPI + SwiftUI 코드베이스에서 **구방향 기능을 걷어내고**(5종 페르소나·설화 채팅·일지·민화), **자격 요건 위험을 고친다**(KTO 캐시 TTL, 서비스명, 출처 표기, 위치 전송 경로). 새 기능은 심사용 ID/PW 로그인과 계정 삭제 두 개뿐이다. 재생 엔진·결제·픽셀아트 UI는 단계 1 이후다.

**Tech Stack:** FastAPI · SQLite · pytest · SwiftUI · Firebase Auth · XcodeGen

**연관 문서:** [`../기획/설계_현장경험_엔진_v1.md`](../기획/설계_현장경험_엔진_v1.md) · [`../관광데이터 개발 공모전/_심사요약.md`](../관광데이터%20개발%20공모전/_심사요약.md) · [`../../DESIGN.md`](../../DESIGN.md)

## Global Constraints

- **서비스명은 `놀멍봅서`**, 영문 식별자는 `Nolmeongbopseo`. 구명 `탐라담`·`JejuFolklore`를 사용자에게 보이는 문자열에 쓰지 않는다. (Xcode 타깃·번들 식별자는 이 단계에서 바꾸지 않는다 — 앱스토어 등록 후 변경은 위험하므로 별건)
- **KTO 캐시 TTL은 1시간** (`3600`). 완전 제거 금지 — 개발계정 한도가 오퍼레이션당 일 1,000건이다.
- **KTO 출처 표기는 정확히 `출처: ⓒ한국관광공사`**. `TourAPI` 단독 표기 금지, 공사 CI/BI 로고 이미지 사용 금지(텍스트만).
- **사용자 위치를 서버로 전송하지 않는다.** 이건 이 단계에서 지켜야 할 불변식이다. 위치 판정은 단말에서만 한다.
- **심사용 계정은 `openapi` / `2026openapi!`** (공모전 지정 형식, 변경 불가).
- 커밋은 conventional commits. 한 태스크가 한 커밋 이상.
- 백엔드 테스트: `python -m pytest`. iOS는 테스트 타깃이 없으므로 **빌드 성공**으로 검증한다.
- **iOS 빌드 명령.** 첫 태스크 시작 전에 스킴 이름을 한 번 확인하고, 이후 모든 `<스킴>` 자리에 그 값을 넣는다.
  ```bash
  xcodebuild -list -project ios/JejuFolklore.xcodeproj   # Schemes: 목록에서 확인
  xcodebuild -project ios/JejuFolklore.xcodeproj -scheme <스킴> \
    -destination 'generic/platform=iOS Simulator' build 2>&1 | tail -5
  ```
  `project.yml`을 수정한 태스크에서는 빌드 전에 `cd ios && xcodegen generate && cd ..`를 먼저 실행한다.
- **픽셀아트 UI는 이 단계 범위가 아니다.** 기능만 만들고 스타일은 단계 1에서 `DESIGN.md`에 따라 입힌다.

"""심사용 ID/PW 로그인 → Firebase 커스텀 토큰 발급.

공모전 요건상 심사위원이 지정 형식 계정으로 로그인해 서비스 전체를 확인할
수 있어야 한다(로그인 실패 시 심사 제외). 일반 사용자는 소셜 로그인을 쓰고,
이 경로는 심사 계정 하나만 통과시킨다.

계정 정보는 환경변수로 둔다 — 비밀번호를 코드에 커밋하지 않는다.
    REVIEW_ACCOUNT_ID=openapi
    REVIEW_ACCOUNT_PASSWORD=2026openapi!
    REVIEW_ACCOUNT_UID=review-openapi
"""
from __future__ import annotations

import hmac
import os

from fastapi import APIRouter, HTTPException, Request, status
from pydantic import BaseModel
from slowapi import Limiter
from slowapi.util import get_remote_address

router = APIRouter(prefix="/auth", tags=["auth"])
limiter = Limiter(key_func=get_remote_address)

REVIEW_UID = os.getenv("REVIEW_ACCOUNT_UID", "review-openapi")


class LocalLoginRequest(BaseModel):
    user_id: str
    password: str


class LocalLoginResponse(BaseModel):
    custom_token: str


@router.post("/local", response_model=LocalLoginResponse)
@limiter.limit("10/minute")
def local_login(request: Request, body: LocalLoginRequest):
    expected_id = os.getenv("REVIEW_ACCOUNT_ID", "")
    expected_pw = os.getenv("REVIEW_ACCOUNT_PASSWORD", "")

    # 타이밍 공격을 피하려고 compare_digest를 쓴다. 두 값 다 비어 있으면 항상 실패.
    id_ok = bool(expected_id) and hmac.compare_digest(body.user_id, expected_id)
    pw_ok = bool(expected_pw) and hmac.compare_digest(body.password, expected_pw)
    if not (id_ok and pw_ok):
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="아이디 또는 비밀번호가 올바르지 않습니다.",
        )

    from services.auth import create_custom_token  # 지연 import: Firebase 미설정 시에도 모듈 로드 가능

    token = create_custom_token(REVIEW_UID)
    if token is None:
        raise HTTPException(
            status_code=status.HTTP_503_SERVICE_UNAVAILABLE,
            detail="인증 서버가 준비되지 않았습니다.",
        )
    return LocalLoginResponse(custom_token=token)
